# Explore — flow where "<query>" retrieval subcommand (MVP)

## Goal

Ship **one CLI command** — `flow where "<query>"` — that answers "where did I implement X?" in a single hop across three local sources: **repo code + tests**, **archived SDD specs**, and the **graphify graph index** (fail-open). Output is plain text with explicit `CODE / TESTS / SDD / GRAPH` sections so the user gets a structured answer without juggling 5 manual grep calls. MVP is intentionally small: no engram backend, no JSON, no ranking, no commit SHAs — just fast, deterministic, zero-deps retrieval over files that already exist.

## Why now

**User pain point.** Asking "where did I implement JWT?" today requires 5 manual hops: `rg src/` for code, `rg openspec/changes/archive/` for archived specs, an engram `mem_search`, a graphify query, and a `rg tests/` for coverage. Each hop burns tokens, time, and context. The user wants one CLI command with structured text output that they can paste into a follow-up prompt.

**Prior-art avoidance.** The `2026-06-26-vector-semantic-search` change (#4, archived) targeted a fundamentally different problem: **semantic retrieval over engram observations using embeddings** (sqlite-vec + sentence-transformers, ~500MB torch dep, 2 chained PRs, ~2.8k LOC). `flow where` is **grep over files that already exist on disk** — no embeddings, no new dep, no infra. We learn from #4's architecture and process discipline (ABC seams, fail-open graphify, BDD-first, strict TDD multiplier) but explicitly do NOT repeat its scope.

**Why now and not "later"**: the user's retrieval pain is acute, the MVP is small enough to land in a single PR, and all three data sources are local-first with no setup ceremony.

## Prior art learnings (from `2026-06-26-vector-semantic-search` #4)

- **ABC + fail-open pattern is the established seam.** `graphify_query.query_nodes` returns `[]` on every error path (missing binary, missing `graph.json`, non-zero exit, timeout). `flow where` MUST reuse this discipline for the GRAPH backend — check `graph.json` existence, query if present, silently print `unavailable / no graph index found` otherwise. **No exit-2 on missing graph.**
- **Single-purpose module, not inline in `cli.py`.** `graphify_query.py` is the precedent: thin wrapper module (~266 LOC), imported by `cli.py`. `flow where` follows the same shape: new `src/flow_engineering/where.py` (~150 LOC) with three pure-function backends, imported by one new `@main.command()` in `cli.py`.
- **Test pattern is BDD + unit.** `tests/bdd/req_<n>_<topic>.feature` + `tests/bdd/test_<topic>_steps.py` + `tests/unit/test_<topic>.py`. Use `CliRunner` + `monkeypatch` of any IO seams (no global `_default_save_backend` for `where` — there is no backend, it's pure file IO).
- **Strict TDD multiplier is ~6x.** #4 forecast ~470 LOC, landed ~2.8k LOC. MVP forecast ~150 LOC → realistic ~900 LOC total (tests included). Still well under the 400-line review budget for a single PR because we have no ABC and no optional dep.
- **Output structure matters.** #4 ships a table with `rank / id / title / score`. `flow where` is NOT ranked — output is grouped by source (`CODE / TESTS / SDD / GRAPH`) with `path:line` per hit. Simpler contract, fewer rows of code.
- **Optional-dep / activation gates are NOT needed here.** `rg` ships everywhere (or `grep -rn` as POSIX fallback). Graphify is invoked via subprocess or direct JSON read — no Python import. **Zero new dependencies.**
- **Graph index may legitimately not exist.** Per Engram #83, the `graphify.js` plugin is wired but the `graphify-out/graph.json` file is generated by the user's own workflow (not by us). MVP MUST verify-on-call: this is exactly what the fail-open pattern protects.

## MVP scope (single PR)

### CLI surface

- **New** `@main.command()` decorator in `src/flow_engineering/cli.py` registering `flow where`.
- Single positional `query` argument (string).
- Optional flags:
  - `--limit N` (default 20) — max hits per backend section.
  - `--no-graph` (default: graph enabled) — opt-out flag for users who want to skip the graphify check entirely.
- Exit code: `0` always (even with zero hits — empty sections just render). `2` only on internal error (e.g., `where.py` raised unexpectedly).
- Output: stdout, plain text, UTF-8. See "Output contract" below.

### Three backends (in `src/flow_engineering/where.py`)

1. **Repo grep (CODE + TESTS sections)** — `subprocess.run(["rg", "--line-number", "--no-heading", query, "src/", "tests/"])` with `check=False`. On `rg` exit 1 (no matches) → empty sections. On `rg` missing or exit 2+ → fall back to `grep -rn` (POSIX) via `shutil.which("rg") is None` branch. Parse lines into `path:line[:col]`. Split hits: `path.startswith("tests/")` → TESTS section, else → CODE section.
2. **SDD archive grep (SDD section)** — `subprocess.run(["rg", "--line-number", "--no-heading", query, "openspec/changes/archive/"])` with the same fallback to `grep -rn`. Cap at `--limit` hits.
3. **Graphify fail-open (GRAPH section)** — read `graphify-out/graph.json` (default path `Path(r"c:\dev\proyects\flow-engineering\graphify-out\graph.json")`, overridable via `--graph-path`). If file missing OR unreadable OR no `nodes` key → print `unavailable / no graph index found` (single line, no stack trace). Otherwise tokenize query, score nodes by Jaccard over `label + id + source_file` (reuse `graphify_query.jaccard_fallback` pattern, no new dep on the `graphify` CLI), top-K by score.

### Output contract (text)

```
CODE
- src/flow_engineering/auth.py:42
- src/flow_engineering/middleware.py:18

TESTS
- tests/unit/test_auth.py:23
- tests/bdd/req5_nonbreaking.feature:14

SDD
- openspec/changes/archive/2026-06-25-decision-code-linking/spec.md:88 REQ-7 mentions JWT signing key validation

GRAPH
- src/flow_engineering/auth.py:42 — module:auth (confidence 0.78)
```

- Sections are **always rendered** in the order CODE → TESTS → SDD → GRAPH, even when empty.
- Empty section prints `(no matches)` on its own line (keeps output grep-friendly).
- GRAPH unavailable → `unavailable / no graph index found` (exact string, deterministic).
- One hit per line. SDD and GRAPH hits MAY include a trailing prose snippet (first 80 chars of the matched line) when available; CODE/TESTS hits are bare `path:line`.

### Module structure (`src/flow_engineering/where.py`, ~150 LOC)

```
DEFAULT_LIMIT = 20
DEFAULT_GRAPH_PATH = Path(r"c:\dev\proyects\flow-engineering\graphify-out\graph.json")

@dataclass(frozen=True)
class WhereHit:
    path: str
    line: int
    snippet: str | None = None

@dataclass(frozen=True)
class WhereResult:
    code: list[WhereHit]
    tests: list[WhereHit]
    sdd: list[WhereHit]
    graph: list[WhereHit] | None  # None == unavailable

def grep_repo(query, *, limit=DEFAULT_LIMIT, cwd=Path.cwd()) -> tuple[list[WhereHit], list[WhereHit]]
def grep_sdd(query, *, limit=DEFAULT_LIMIT, cwd=Path.cwd()) -> list[WhereHit]
def grep_graph(query, *, limit=DEFAULT_LIMIT, graph_path=DEFAULT_GRAPH_PATH) -> list[WhereHit] | None
def where(query, *, limit=DEFAULT_LIMIT, no_graph=False, graph_path=DEFAULT_GRAPH_PATH) -> WhereResult
def render_text(result: WhereResult) -> str
```

The CLI handler is ~15 LOC: parse args, call `where(...)`, `click.echo(render_text(...))`.

### Tests

- **`tests/unit/test_where.py`** (~250 LOC) — pure-function tests:
  - `grep_repo`: hits split correctly into CODE vs TESTS; `--limit` truncation; rg-missing falls back to grep; empty query returns empty lists.
  - `grep_sdd`: archive path correctness; limit truncation; missing `openspec/changes/archive/` returns `[]` (no error).
  - `grep_graph`: missing file returns `None`; empty nodes returns `None`; valid nodes return ranked hits; token-overlap scoring monotonicity.
  - `where`: integration of three backends; `--no-graph` shortcut; section order is stable.
  - `render_text`: empty-result rendering; unavailable-GRAPH rendering; ordering preserved; UTF-8 safe.
- **`tests/bdd/req_where.feature`** + **`tests/bdd/test_where_steps.py`** (~250 LOC) — BDD scenarios:
  - Scenario 1: query with matches across all four sections.
  - Scenario 2: query with matches in CODE only.
  - Scenario 3: query with zero matches across all sources.
  - Scenario 4: graphify-out absent → GRAPH renders unavailable message.
  - Scenario 5: `--no-graph` skips GRAPH section entirely.
  - Scenario 6: `--limit N` caps each backend's output.
  - Scenario 7: exit code is `0` even with zero matches.

## Out of scope (deferred to Opción media / v0.x follow-up)

- **Engram backend.** Explicitly excluded per user directive ("avoid protocol coupling in MVP"). The 4th backend would be `engram_io.EngramClient.mem_search(query, ...)` filtered by topic_key prefix. Add when the user has the MCP plumbing stable AND wants ranked cross-project recall.
- **`--json` flag.** No machine-readable output in MVP. Text is the contract. JSON can come in v1.x once we know what users pipe it into.
- **Ranking / scoring.** No RRF, no cosine, no BM25. Hits render in the order the backend produces (rg's natural order = file-path sort, then line asc). Adequate for "where did I implement X?" — the user reads the top 5 hits and stops.
- **Commit SHA references.** No `git log -S` integration. Adds a subprocess + a parse pass for negligible value at MVP scale.
- **REQ-NN cross-linking.** No automated detection that "this hit is the code for REQ-7". Could be a v1.x follow-up using the existing `binding.split_prose_and_refs` helper.
- **Confidence scores on CODE/TESTS/SDD.** Only GRAPH carries confidence (it's already in `graph.json`). Repo hits are binary: matched / not matched.
- **Watch / daemon mode.** Not relevant for a read-only CLI subcommand.
- **Persistent index or cache.** Every `flow where` call is fresh. No `~/.flow-engineering/where_cache.json` — rg is fast enough.
- **Multi-project federation.** Single-project scope (`Path.cwd()`). Federation is owned by `cross-project-federation` (shipped).

## Proposed approach

Single PR, strict TDD, BDD-first. Phase plan:

1. **propose** (~30min): lock MVP scope in `proposal.md`, fill `## Intent`, `## Scope`, `## Approach`, `## Risks`, `## Success Criteria`.
2. **design** (~30min): resolve the 3 open questions (see below) in `design.md`; document `WhereResult` dataclass shape, render contract, fallback strategy.
3. **spec** (~30min): `spec.md` with 4–5 requirements (REQ-WHERE-1..5) covering CODE/TESTS/SDD/GRAPH render contract, fail-open semantics, limit flag, --no-graph flag.
4. **tasks** (~15min): `tasks.md` with one task per backend + CLI wiring + BDD + unit tests; verify-phase checklist.
5. **apply** (~90min, single PR):
   - RED: write `tests/unit/test_where.py` + `tests/bdd/req_where.feature` first; confirm 1383/1383 baseline + new tests failing as expected.
   - GREEN: implement `where.py` + `cli.py` registration; tests pass.
   - REFACTOR: tighten dataclasses, ensure CLI handler ≤15 LOC, run mypy + ruff clean.
6. **verify** (~15min): run full test suite (must hit 1383 + ~25 new = ~1408/1408 passing); ruff + mypy clean on changed files; smoke-test `flow where "JWT"` from the project root.
7. **archive** (~10min): `flow archive flow-where-mvp` writes `archive-report.md`, syncs delta to main `openspec/specs/`.

## Risks

| Risk | Likelihood | Mitigation |
|---|---|---|
| `rg` is not installed on some Windows machines | Med | Fall back to `grep -rn` via `shutil.which("rg")`; document in --help |
| `grep -rn` is also missing (sandboxed env) | Low | Return empty sections with `(no matches)`; do NOT exit non-zero |
| `graphify-out/graph.json` is malformed JSON | Med | Wrap `json.loads` in `try/except (OSError, json.JSONDecodeError)`; return `None` → GRAPH unavailable |
| `query` contains regex metacharacters that rg interprets | Low | Quote the query in the subprocess call (`shlex.quote`); both rg and grep accept literal queries when quoted |
| `openspec/changes/archive/` does not exist (fresh repo) | Low | `grep_sdd` returns `[]`; SDD section renders `(no matches)` |
| Output is too long to be useful (rg returns 1000+ hits) | Med | `--limit` flag (default 20) caps each backend's output; document the cap in --help |
| Token cost: large CODE section on monorepos | Low | User can `--limit 5`; future flag `--path` to narrow scope (out of MVP) |
| Tests for `grep_repo` hit the real `src/` + `tests/` (not isolated) | Med | Use `monkeypatch.chdir(tmp_path)` and create a small fixture tree in `tmp_path`; tests do not depend on the real repo contents |
| `flow where` becomes a workaround for missing engram CLI | Low | Out-of-scope note in proposal; engram backend is explicitly deferred, not rejected |
| User changes their mind on engram backend mid-apply | Med | Stop work, re-propose; the module structure (`grep_graph` as a separate function) makes adding a 4th backend trivial |

## Open questions (must resolve in design phase)

1. **`--no-graph` vs. auto-detect.** Should the GRAPH section be opt-in (`--graph` flag, default off) or opt-out (`--no-graph`, default on)? **Recommend default ON** because (a) it's free when `graph.json` is absent (returns `unavailable`), (b) the user pain explicitly includes graphify, (c) opt-out is easier to remember than opt-in. Confirm in design phase.
2. **Snippet rendering policy.** Should CODE/TESTS hits show a snippet (first 80 chars of the matched line) or stay bare `path:line`? Bare is simpler and matches `rg -n` ergonomics; snippets add value for SDD hits where the line context matters. **Recommend: CODE/TESTS bare, SDD + GRAPH with snippet.** Confirm in design.
3. **Sort order within a section.** rg's default is path-asc, line-asc. SDD archive hits should match. GRAPH should sort by confidence desc. **Recommend: stable, document in spec.** No reorder knobs in MVP.

**Why**: User pain — 5 manual hops to answer "where did I implement X?" burns tokens and time. MVP is intentionally tiny (no engram, no JSON, no ranking, no new deps) to ship in one PR.

We borrow its ABC + fail-open discipline and BDD-first test pattern, but explicitly reject its 500MB torch dep, optional-extras activation gate, and 2-PR chain.
